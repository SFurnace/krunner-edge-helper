# 搜索算法说明

## 核心特性

### 1. 多关键词匹配
- 使用空格分隔多个关键词
- 所有关键词都必须匹配（在标题或文件夹中）
- 任一关键词不匹配，该书签不会出现在结果中

### 2. 匹配规则

#### 中文文本（拼音匹配优先）
- **拼音完全匹配**：95-92分
  - 例如："liushui" → "流水"
- **拼音前缀匹配**：88-82分
  - 例如："liu" → "流水"
- **拼音子串匹配**：75-69分
  - 例如："lsx" → "流水线"（在混合文本"EdgeOne 部署流水线"中）
- **原文前缀匹配**：85分
  - 例如："流" → "流水线"

#### 英文文本
- **完全匹配**：100分
  - 例如："edge" = "edge"
- **完整单词匹配（开头）**：98分
  - 例如："edge" → "Edge Browser"
- **完整单词匹配（中间）**：95分
  - 例如："edge" → "Microsoft Edge"
- **前缀匹配**：85分
  - 例如："edg" → "edge"
- **单词前缀匹配**：80分（每后移一个单词减2分）
  - 例如："brow" → "Browser Settings"
- **单词内子串匹配**：65分（每后移一个单词减2分，每偏移一个字符减2分）
  - 例如："eo" → "Edgeone"（需在单词前4个字符内）

### 3. 权重策略
- **标题权重**：1.0
- **文件夹权重**：1.0
- **URL**：不参与匹配
- 采用**最高分**策略（非平均分）
- 标题和文件夹都匹配时额外 +5 分
- 所有关键词都在标题匹配额外 +3 分
- 第一个关键词在标题开头额外 +2 分

### 4. 历史记录权重（History Boost）

当启用历史记录功能时，系统会记录用户的搜索和选择行为，并在后续搜索中提升常用书签的排名。

#### 历史权重计算
```
频率因子 = ln(1 + frequency) / ln(21)  # 使用对数压缩，20次使用接近上限
时间因子 = 0.5 ^ (经过天数 / 30)        # 30天半衰期
历史权重 = 频率因子 * 0.6 + 时间因子 * 0.4  # 频率60% + 时效40%
```

#### 最终得分计算
- **基础分上限**：80分（即使匹配度再高也封顶80）
- **历史加分**：历史权重 × 20分
- **最终分数**：min(基础分, 80) + 历史权重 × 20

这样设计的目的是让高历史权重的书签（使用频繁）可以超越基础匹配分稍低的书签。

#### 示例
用户搜索 "you" 并选择了 "YouTube" 15次（最近30天内）：
- 基础匹配分：92分 → 封顶为 80分
- 历史权重：约0.95
- 历史加分：19分
- 最终得分：99分

另一个书签 "游戏开发中缺失的中间环节" 被选择2次：
- 基础匹配分：95分 → 封顶为 80分
- 历史权重：约0.35
- 历史加分：7分
- 最终得分：87分

因此 YouTube 排名更高。

### 5. 排序规则
1. 按**最终分数**降序排列（base capped at 80 + history up to 20）
2. 分数相同时，按**名称长度**升序（短的在前）
3. 名称长度相同时，按**字母顺序**升序
